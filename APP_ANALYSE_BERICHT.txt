1. ZWECK UND ZIELGRUPPE
--------------------------------------------------------------------------------
DOK-V01 ist eine Windows-Desktop-Anwendung (WPF, .NET Framework 4.8) für die
Blechbearbeitung. Sie verarbeitet technische Zeichnungen (PDF, v. a. Tesla
TSL-*-Zeichnungen) zusammen mit einer Excel-Auftragsdatei.

Hauptworkflow:
  1. Laden (Drag & Drop: Excel, PDFs, ZIP mit PDFs + Excel)
  2. Sortieren & Umbenennen (Match Zeichnungsnummer ↔ Excel-Zeile → 01_…pdf)
  3. Optional: Wasserzeichen (Auftragsnr., Lieferort, Menge, Datum, BG, Material)
  4. Zusammenfügen zu einer _GESAMT_YYYYMMDD_HHMMSS.pdf
  5. Automatische Updates von GitHub-Releases

Zielgruppe: Fertigung / Auftragsbearbeitung mit Tesla-Zeichnungen.
GitHub: Acid31-31/Tesla-Auftragsbearbeitung-und-Druck

Es gibt KEIN Endnutzer-CLI für Sortieren – Batch läuft über MainWindow (WPF).
Nur Tools/PdfDiag ist ein Entwickler-Diagnose-Tool.

6. „KI“ IN DOK-V01 – WAS IST DAMIT GEMEINT?
--------------------------------------------------------------------------------
Es gibt KEIN Cloud-LLM und KEIN Ollama mehr. „KI“ bedeutet:

  a) Lokale Vision (LocalVisionEnabled)
     = pdfium-Raster-Layout: Seite wird gerendert, Dunkelheits-Grid erkennt
       freie vs. belegte Bereiche. Steuert Wasserzeichen-Platzierung.

  b) Lokales OCR (LocalOcrEnabled)
     = Tesseract CLI für Schriftfelder ohne Textlayer (Titelblock-OCR).
     Sprachen: deu+eng (Standard).

  c) Regel-Engine / Plattform-Module
     = Material-Erkennung, Matching, Chat-Hilfe (RuleBasedFallback),
       ThicknessCandidateResolver, Hybrid-Resolver Schriftfeld + Seitenansicht.

Einstellungen: %LOCALAPPDATA%\DOK-V01\ai-settings.xml
  - AiEnabled (Standard: true)
  - LocalOcrEnabled (Standard: true)
  - LocalVisionEnabled (Standard: true)
  - TesseractPath (optional)
  - OcrLanguages (Standard: deu+eng)

Tesseract-Integration (neu, R41-Entwicklung):
  - TesseractBootstrapService: automatische Einrichtung beim Start
  - Gebündelt in Release: tesseract\ neben EXE
  - ensure-tesseract-bundle.ps1 für Release/USB-Build
  - Kein manuelles install-tesseract.ps1 mehr nötig für Endnutzer


7. WASSERZEICHEN-SYSTEM (KRITISCHSTER BEREICH)
--------------------------------------------------------------------------------
7.1 Kategorien
  - Order      Auftragsnummer (fest oben rechts)
  - Location   Lieferort
  - Date       Lieferdatum (LT-…)
  - Quantity   Menge (30X etc.)
  - Material   z. B. VA-3,0mm, ST-2,0mm (mehrzeilig möglich)
  - Bg         Baugruppen-Zeichnung (BG: TSL-…)

Zusätzlich (separater Schritt): Seitenzahlen „Seite-N“ via PdfWatermarkService.

7.2 Pipeline (vereinfacht)
  SmartWatermarkLayoutService.Compute()
    → Platzierungen berechnen (Regeln + Material-Stack)
    → ApplyLearning()
        → WatermarkLearningStore.ApplyToPlacements (pro Zeichnung)
        → ApplyCategoryDefaults (nur wenn Vision AUS)
        → RefinePlacementsToFreeAreas
        → RevalidateMaterialPlacement
        → AiWatermarkPlacementService.EnforceVisionLayout  ← Raster-Korrektur
        → AutoLearnSuccessfulPlacements (speichert CategoryDefaults)

7.3 Koordinaten-Konvention Material (Alignment=1, zentriert)
  - placement.X = Mitte des Textblocks
  - placement.Y = Baseline der OBERSTEN Zeile (NICHT Unterkante!)
  - Anker-Suchfunktionen liefern anchorBottomY (Unterkante)
  - Umrechnung: topBaselineY = anchorBottomY + blockHeight - lineHeight
  - Prüfung Placements: materialYIsBottomAnchor: false
  - Prüfung Anker-Suchergebnisse: materialYIsBottomAnchor: true

7.4 Regeln für korrekte Platzierung
  - Material NUR in Randkorridoren (links, oberer Rand, Streifen über Schriftfeld)
  - NIEMALS Zeichnungsmitte, NIEMALS Toleranztabelle
  - IsInsideDrawingCore und IsOverlappingTitleBlock VOR Dunkelheits-Check
  - KEINE gelernten Material-Positionen aus XML anwenden (seit R41)
  - EnforceVisionLayout läuft wenn PdfRasterLayoutService.IsAvailable
    (nicht nur wenn KI-Schalter an)

7.5 Relevante Dateien
  Services/SmartWatermarkLayoutService.cs    Layout aller Kategorien
  Services/AiWatermarkPlacementService.cs    EnforceVisionLayout, Zonen
  Services/PdfRasterLayoutService.cs         Raster, IsInsideDrawingCore,
                                             IsOverlappingTitleBlock,
                                             IsPlacementAcceptable
  Services/WatermarkLearningStore.cs         XML-Lernspeicher
  PdfWatermarkService.cs                     Schreibt finale Positionen in PDF


8. BEKANNTE PROBLEME UND SYMPTOME (STAND 05.07.2026)
--------------------------------------------------------------------------------
8.1 Nutzer-Meldung (aktuell, hoch priorisiert)
  Wasserzeichen werden falsch platziert:
  - BG-Text über Randlinie / falscher Bereich
  - Material (z. B. ST-8,0mm) über Toleranztabelle „ZULÄSSIGE ABWEICHUNGEN…“
  - Seitenzahl über DATEIPFAD im Schriftfeld

8.2 Diagnose PdfDiag --watermark-test (26 TSL-PDFs, vor Fix-Versuch)
  Ergebnis: 0 PDFs frei platziert, 156 Probleme („AUF BAUTEIL“)
  Material-WERTE waren korrekt (VA-3,0mm etc.), Positionen falsch.
  Exit-Code 3 = Platzierungsprobleme.

8.3 Material-Extraktion (Batch-Test, gleiche 26 PDFs)
  Ergebnis: 26/26 mit Wasserzeichen-Materialtext, 0 fehlend.
  OCR/Tesseract + Regeln funktionieren für Erkennung.
  Ausreißer:
  - TSL-11367: VA-20,0mm statt vermutlich 5 mm (Seitenansicht-Zahl)
  - TSL-11090, TSL-11251: nur „ST“ ohne Dicke

8.4 Historische Fallstricke (AGENTS.md)
  - Material bei rel 0.59/0.48 überall → schlechte CategoryDefaults im Lernspeicher
  - Material auf Schriftfeld unten links → Fallback ohne Raster (R41 behoben)
  - Prüfung „OK“ trotz Text auf Zeichnung → falsche Y-Geometrie (R41 behoben)
  - pdfium fehlt / 0x8007000B → falsche Bitness nach Update
  - 20 mm statt 5 mm → Seitenansicht als Dicke interpretiert

8.5 Lernspeicher
  Pfad: %LOCALAPPDATA%\DOK-V01\Learning\watermark-placements.xml
  Bei falschen Wasserzeichen: Datei löschen, Ablage leeren, neu sortieren.
  Material wird seit R41 NICHT mehr aus XML übernommen (ApplyToPlacements überspringt).


9. ÄNDERUNGEN IN AKTUELLER ENTWICKLUNGSSITZUNG (UNGETESTET VOLLSTÄNDIG)
--------------------------------------------------------------------------------
Folgende Fixes wurden implementiert, Build Debug erfolgreich, App gestartet
aus: E:\Programierung\PDF Sortieren\bin\Debug\DOK-V01.exe

  a) PdfRasterLayoutService.IsInsideDrawingCore
     Zeichnungskern war falsch definiert (nur schmaler Streifen 10–22% von
     unten statt oberer Zeichnungsbereich). Korrigiert auf:
     coreBottom = titleTop + 20, coreTop = pageHeight - 24

  b) PdfRasterLayoutService.IsInsideTitleBlock
     Schriftfeld galt nur rechts (ab 58% Blattbreite). Toleranztabelle links
     wurde nicht geschützt. Korrigiert: volle Breite im unteren Streifen
     (untere ~22% der Seite).

  c) AiWatermarkPlacementService.IsPlacementGood
     materialYIsBottomAnchor war fälschlich true für Material-Placements.
     Korrigiert auf false (Placements = top baseline).

  d) PdfRasterLayoutService MeasureAnchorBlockDarkness / IsPlacementAcceptable
     Y-Geometrie für alignment=1 (zentriert) bei Dunkelheitsmessung korrigiert.

  e) PdfWatermarkService DrawPageNumberOnPage
     Seitenzahlen von unten Mitte nach oben rechts verschoben (Alignment 2).

  f) TesseractBootstrapService + Bundle-Integration (separate Aufgabe)

Nutzer soll testen mit Debug-EXE, nicht mit C:\Program Files\DOK-V01\.
Lernspeicher vor Test löschen.
